# 世界执行规则

行动之前，先读本技能、当前与上级的 README、行动来源及其 intent（意图）、相关的实际物品，以及提供的游玩记录。README 定义地点和已知出口；Chalk 说明眼前的行动和生成意图；本技能规定连续性。intent 字段是写给作家（Writer）的文字说明，不是另一条引擎命令。

所有正文和提示词都使用简体中文；普通文件夹和文件名使用 ASCII 小写 kebab-case。保留协议标识符和已有素材路径。针对行动叙述一个具体后果，不要替玩家编造决定。只有在玩家要求拿取时才移动实际物品。阅读不等于持有。提交不会消耗物品。不要把人当作物品栏里的东西。

写之前，先列出本次行动需要的文件。宣称完成前把它们读回来确认；任何解锁凭证都放在最后创建。失败时报告缺少的部分，保持关卡锁定，重试时只修复缺少的部分。重复点击不会重复发放奖励。事实存进相关实体的正文和扁平的 status.data，不要新建状态文件。

进入或提交时绝不自动掷骰。任何可选掷骰之前，先公开公式、阈值、理由、概率、普通奖励与大奖励、失败结果、小概率的实际损害，以及放弃的选项。等待玩家按这些确切条件掷骰。绝不通过删除结果来重掷。骰子不能改变已确立的事实或他人的同意。

生成的地点需要一个 README、两个有意义的物品、一个可操作的 Chalk 和一个返回关口。居民可以是一张不可携带的便条，写明名字、职业、可见的举止和有限的知识，由作家来扮演；不要编造未注册的角色按钮。只有 README 并不代表完成：检查并修复缺失的文件，重访时绝不重新生成这个地点。先写文字，然后针对这一确切场景只调用一次 generate_image。只把返回的、实际存在的素材挂到 bg；删除冲突的 bgVideo。图片生成失败时文字仍可游玩，要如实报告，且不自动重试。1–2 分钟的段落是设计预算，不是延迟承诺。

## 信封与手机
读取它们的当前位置，即使已被移到 player/. 中也一样。打开信封会生成一条简短的当代消息，其中包含一个地点或人物，以及与玩家个人相关的利害。把这条消息和公开的 Context（状况）更新到实际物品上。仅检查信封外表不会揭示消息内容。电话通话是虚构的角色扮演；保存实际的对话内容，以及一个具体的声音或话中提到的地标。两件物品在被发现之前都不会暗中提供任何事实。

## 打开门
初始扩展只有一处：world/outside。再次读取两件实际物品及其公开的 Context。若都未使用，不提供任何隐藏事实。若信已打开，尊重其中的地点或人物。若打过电话，体现其中听到的细节或地标。若两者都发生了，两者都要兼顾。若都没发生，创造一个合理的当代地点和一个小机会；不要惩罚好奇心，也不要默认编造邪教。

写入 world/outside/README.md、resident.md、found-object.md、01-arrival.md 和 return.md。返回关口的目标是 map。居民是一张不可携带的便条：名字、当前在做的事、一句他们会说的话，以及他们不知道的事。找到的物品应与某个已揭示的细节相连，但不揭开整个谜团。到达 Chalk 提供交谈、调查和返回；其 intent 只允许一次有明确动机的进一步发现，不能形成无限分支。在上级的门里加一句具体的话，说明门外现在有什么。

验证全部五个文件，即使 README 已经存在。修复不完整的场景时，不要换成别的居民或地理。文字完成之后才调用一次 generate_image：克制、有电影感的当代氛围，包含实际的天气和物品，不要 UI 或文字。不要把手机或信做成巨大的背景道具。把返回的素材存到 README 的 bg。缺少图片时显示为待生成的插图，而不是伪造的成功。

## 第一分钟的奖励
玩家与居民交谈时，引用一个玩家真正提供或注意到的细节，然后用他们了解到的内容更新 resident.md。调查找到的物品会得到一个可用的事实或一件小物品，而不是解开整个阴谋。点睛之处在于：在新出现的门外，认出某样来自屋内的东西。返回时使用 map，并保留门外场景。不需要安排剧情结局。

## 直接行动与作家回合
choice_actions 把稳定的 choice.options ID 映射到已实现的 UI 配方：read(paths)、take(paths)、stage(paths)、enter(target)、character(character)、reply(text)、writer(可选提示词)。阅读、拿取、在已有场景间移动和摆放材料都不会调用作家。stage 不会提交或执行。未知内容、新的承诺、虚构通话和生成仍需要明确的作家输入。给新选项加上这些绑定，同时保留自由角色扮演。绝不编造动作类型、脚本执行，或引用不存在的可读文件。

## 清晰的玩家引导
使用简短、熟悉的语言。说明发生了什么，以及玩家接下来能做什么。解释线索时依次讲：事实、可能的含义、去哪里查证。保持氛围，但不要隐藏目标。新的骰子必须使用 1d10、2d10 或 1d100，并在玩家决定掷骰之前让条件和后果可见。

## 技能与检定
这个世界用类 D&D 的技能（world.json 的 `rules`）。主角的角色卡是 player/README.md 的 `sheet:`（属性调整值与熟练技能），同伴的在各自的角色 README 里。检定是 d20 + 技能调整值对抗 DC（简单 10、普通 12、困难 15、极难 20），情境给出时按优势或劣势掷；天然 20 必定成功，天然 1 必定失败。主角尝试没有把握的事时，用合适的技能和 DC 调用 skill_check，然后停下等玩家掷；按结算出的档位叙述。同伴可以为自己的行动检定（skill_check，actor "self"）。不要在正文里替骰子决定结果；感情、承诺与同意从不检定。
