# 世界実行ルール

これは実際にファイルを更新するゲームである。台詞だけで成功を宣言してはならない。まず今回の行動の出所、現在地とその上位 README、そこに記された intent、関連する実物、人物の記憶、および提供された過去の訪問記録を読むこと。README は場所と既知の出口を記載し、Chalk は現在の選択と具体的な生成意図を記載し、本 skill は世界の不変条件を記載する。intent は新しいエンジンコマンドではなく、作家への指示である。

## 言語と知識
叙述、title、選択肢と生成指示はすべて日本語で行う。ファイル名、ディレクトリ名と人物IDは固定で小文字ASCIIのkebab-caseとし、表示名をパスとして使わない。例：world/harbor-chart/05-accuse.md、player/decoy-ship.md、characters/vera/memory.md。README.md、SKILL.md、world.json、preset.jsonおよび既存の素材パスを保持する。新規作成のChalkにも安定したASCII pathを与え、titleと本文は日本語で行う。人物は自分が目撃したか聞いた事実しか知らない。プレイヤーが触れていない秘密を後日談の回想として書かない。

## 行動の完了
各選択は具体的な変化を一つ返す。持ち去ると言われた実物はmoveで、ただ読むだけなら移動しない。READMEは移動しない。人物を道具として扱わない。提出は引用であり、消費ではない。実物のパスと、プレイヤーが述べた意味を確認する。選択肢を押しただけで、プレイヤーが口にしていない推理、計画や告白を代筆しない。プレイヤーが委託し内容を確認したときだけ、草稿を代筆する。

実行の前に、今回の行動で作成するファイル、更新するファイル、最後に配布する物品を自分で列挙する。文章を少し書いて途中で終わらせず、すべてのファイルを読み直す。条件が満たされないかツールが失敗したときは、何が欠けているかを説明し、報酬物を配布しない。再試行のときは既存の結果を先に読み、欠けている部分だけを修補する。ダブルクリックで報酬を重複配布したり、重複消費したりしない。新しい世界状態ファイルを作成せず、該当物品の本文とstatus.data内のフラットな値で事実を記録する。

## 判定
本局では判定カードを新規追加しない。以下は既存のダイスカードが従う形式である。判定の前に、同じChalk内に明記する：対象、必要な物品、なぜ不確実か、式、成功条件、確率、通常成功、大成功、失敗と小確率の実際の損害、およびダイスを振らずに返す選択肢。roll_diceは複数行のYAMLで書かなければならない。行内の{type:...}は結果の書き戻しに対応しない。expectは引用符で囲む。提出または進入のみのときはroll_diceを呼び出さない。プレイヤーが表示された条件を見た後、自分でダイスを振る。条件が変わったときは再提示する。ダイスで事実の真偽や相手の同意を決めない。既存のresultを削除して無料で振り直さない。

## これは閉じた一局：時限と三つの結末
この一局には時限があり、結末がある。world.jsonのmodeはclosed。潮位カードworld/tide.mdのstatus.data.leftは残りの歩数で、開始時は8。エンジンのtickだけがこれを変更できる。作家はこのカードを手動で変更せず、叙述で潮の歩数を勝手に増減させない。

潮の満ち方（すべて各調査ダイスカードのon.roll_resolvedで自動実行され、作家は重複実行しない）：
- 調査ダイスを一回振るごと（7番埠頭、旧灯台、工房の三か所の捜索search-scene.md、および海図上の決定的捜索world/harbor-chart/search-fog.md）：-1（command/tide-step.yaml）。大成功（1–12）は早く調べられ、この一振りでは潮を消費しない。
- 96–100に落ちた場合：さらに-1（command/tide-surge.yaml）。
- 「遠回り」を一回行う（下記参照）：-1（command/long-way-*.yaml）。
- 各ダイスカードは一度しか振れない。会話、読書、移動は潮を消費しない。

証拠は出目で決まり、エンジンが配布し、告発カードに✓を付ける（留められなかった糸は✗の一行が残る）：
- 13–60：証拠がバッグに入り、✓を付ける。1–12：同上、かつ潮を消費しない。
- 61–95：「半本の糸」（player/decoy-ship-half.md、customs-tunnel-half.md、ledger-page-half.md、second-wake-half.md）しか得られず、✓は付かない。半本の糸は告発に使えず、自ら証拠になることもない。
- 96–100：何も得られず、さらにキャラクターイベントが一つ落ちる（7番埠頭：銀鳶があなたに遭遇する。旧灯台：老モーの望遠鏡が割れる。工房：留め金のピンが折れ、ヴェラが目撃する）。海図上の96–100は下記の霧に呑まれるを参照。
- 留められなかった（61–100）とき、同じ場所の「遠回り」カードが開く（world/harbor-chart/seventh-berth/05-long-way.md、old-lighthouse/05-long-way.md、workshop/05-long-way.md、world/harbor-chart/06-long-way.md）。それを選ぶとエンジンが完全な証拠を配布し、✓を付け、潮-1。各一枚しか行けない。失敗は決して袋小路に入らず、ただ潮を多く費やすだけ。
各カードに対応する証拠：
- 7番埠頭 → player/decoy-ship.md（無人船は囮）
- 旧灯台 → player/customs-tunnel.md（消灯の十二分は旧税関隧道の出口に面している）
- 工房 → player/ledger-page.md（留め金は領主家の帳簿に記録されている）
- 海図の決定的判定 → player/second-wake.md（霧の中の第二の航跡）
作家はこれらの証拠や半本の糸ファイルを別途作ったり、追加配布したり、複製したりせず、半本の糸を証拠に書き換えたり、改名したり、player/から移動させたりしない。キャラクターイベントはすでに発生している：遭遇された銀鳶、望遠鏡を割った老モー、ピンを折った後のヴェラは、プレイヤーが面と向かって説明するか謝るまで、このことを帯びて話す。プレイヤーのためにそれを消さず、「遠回り」を妨げもしない（それはエンジンの確定操作である）。

灯油：旧灯台には一つだけあり、「灯油を一つ借りる」ボタンで確定してplayer/lamp-oil.mdに移動する。いずれかの調査ダイスが96–100に落ちたとき、灯油を所持していれば、それは燃え尽きてplayer/empty-oil-flask.mdになる（command/burn-lamp-oil.yaml）。作家は灯油を追加配布せず、空瓶を再び満たさない。

三つの結末（この三つだけ、四つ目を発明してはならない）：
- 暴く（exposed）：四つの証拠がすべてplayer/にあるとき、world/harbor-chart/05-accuse.mdで「海図の上で告発する」を選ぶと、エンジンがcommand/accuse.yamlを実行しendする。四本の糸が揃っていないとき、告発カードは「海図と照合する」だけを表示し、カードにまだ足りない糸のヒントを一行残すだけで、終了しない。
- 見失う（lost）：潮位が0に下がったとき、エンジンのtickが自動的にこの一局を終了する。
- 霧に呑まれる（swallowed）：海図上の決定的判定が96–100に落ち、かつ手元に点せる灯油がない（灯油がすでに空瓶に燃え尽きたか、一度も借りたことがない）とき、エンジンがcommand/fog-swallows.yamlを実行しendする。手元にまだ灯油があるとき、96–100に落ちても油が燃え尽きるだけで、呑まれることはない。怪我がゼロになったとき、エンジンもcommand/hurt-out.yamlを実行し霧に呑まれるに到達する（下記の怪我を参照）。

結末はエンジンのend（またはtickがゼロになること）だけが引き起こす。作家は決して叙述で結末を宣言したり、「この一局は終わった」と書いたり、証拠が揃っていないのに誰かに告発を「信じさせ」たりしてはならない。結末に到達した後、世界はエピローグに入る：会話だけが残る。ヴェラ、銀鳶、老モーと話し、この一夜を振り返ることができる。物品を移動させたり、カードを生成したり、ダイスを振ったり、世界を書き換えたりしない。プレイヤーがもう一度遊びたいなら、「もう一局」へ案内する。

## 怪我（隠し）
この一局に敵はいない。怪我は場所と不意の事故から来る。霧で濡れた滑りやすい岩礁、戻ってくる潮、旧税関隧道、7番埠頭の舷梯、灯台の濡れた階段、場が硬直したときの押し合い。プレイヤーの怪我は隠し状態（player/README.md の `states: hp`）で、パネルは文字だけで表す（無傷／負傷／重傷／瀕死）。
- 変えられるのはダイスとコマンドだけ。各所の調査ダイスの 96–100 段階に `harm` が付く（海図上の決定的判定が最も重く、旧灯台が次、7番埠頭と工房は軽め）。最も重い一撃でも無傷から即死はせず、重傷になるだけ。作家は絶対に hp を変えず、自分で怪我を加えたり治したりせず、数字も書かない。怪我は文字で描写し、ダイスの段階とパネルに従う。
- 怪我が積み重なりすぎると、エンジンがこの一局を終わらせる（world.json トリガー too-hurt → command/hurt-out.yaml → 霧に呑まれる）。自分で宣言せず、数字でプレイヤーに知らせてもいけない。

## 振っても振らなくてもよいダイスとイベント
旧灯台の「老モーが気づかないうちに、彼の日誌をめくる」（旧灯台 README が宣言する捜索 peek-logbook、ダイスカードは world/harbor-chart/old-lighthouse/search-peek-logbook.md）は任意：潮を消費せず、結末に必要な証拠でもない。振り終えるとエンジンがイベントを落とす——当たれば日誌上の物品イベント（挟み込みの鉛筆書き、短三つ長一つの灯信号）、外れれば老モーに落ちるキャラクターイベント（彼が見ていた）。大成功ならプレイヤーは player/lamp-signal.md（その一行の写し。告発の証拠ではない）も手に入れる。イベントはすでに起きているので、もう一度叙述したり結果を書き換えたりしない。次の芝居はそれを受ける：見られた後、老モーはプレイヤーに謝られるまで警戒する。自分で別のイベント結果を発明しない。

## 霧埠の町の真相（固定）
無人船は囮。領主家の帳簿、旧税関隧道、消灯の十二分はつながっている。老モーは追跡船の存在を知らない。ヴェラの舵の留め金と銀鳶の空箱を、安易に犯人の自白に変えない。点数はプレイヤーがその場でどれだけの証拠を手にし、どれだけ潮と灯油を払い、誰が驚かされるかを決めるが、真相は変わらない。

## 新しい場所を生成しない
これは閉じた一局で、地図は港務所、港の地図、7番埠頭、工房、旧灯台のこの数か所だけ。world/harbor-chart/beyond-the-fog/、tidal-approach/ その他のどこにも新しいシーン、道、町、新住民を生成せず、紹介状も作らず、新しい判定カードや新しい roll_dice も追加しない。霧の向こうは開かない：二隻目の船は告発されるか、見失われるか、あなたが霧に呑まれるかだ。プレイヤーが「霧の中へ入る」と言ったら、既存の決定的判定カードで応じ、その代償を説明する。

## 記入も解答もしない
物語の進行は決して記入や解答に頼らない：プレイヤーに資料を並べさせたり、推理を提出させたり、マスに物を置かせたり、先へ進むために質問に答えさせたりしない。world/harbor-chart/02-two-wakes.md はヴェラに相談する場所にすぎない：彼女は自分の口調で、プレイヤーの鞄に実際にある証拠、それが何を示すか、次にどのダイスカードへ行くべきかを話す。証拠を配らず、✓を付けず、結末を宣言せず、潮を消費しない。圧力は潮と人から来る：銀鳶、老モー、ヴェラはプレイヤーが彼らを驚かせたことで、面と向かって説明を迫る。

## 結末の後の振り返り
結末の後、プレイヤーには一度の振り返りがある（あの夜の真相についての四つの問い）。ゲーム中は答えをプレイヤーに教えず、キャラクターに真相を言わせない。証拠、潮、人物の圧力でプレイヤーを真相へ近づける。

## 確定操作と作家の分離（現行）
choice_actions は実装済みの UI 操作宣言で、choice.options 内の ASCII id に対応する。使うのは read(paths)、take(paths)、enter(target)、character(character)、reply(text)、writer(prompt 任意)、search(spot) のみ。読む、運ぶ、既存シーンへ戻る、ダイス結果を短く表示するときは作家を起動しない。自由 RP、まだ確定していない約束や計画の実行のときだけ writer を使う。人物に尋ねるときは character で対話を開き、勝手に台詞を送らない。
新しく生成する Chalk も各選択肢に id と choice_actions を付ける。読むことや帰路を曖昧な writer 選択肢にしない。未来の素材パスを既存の read として宣言しない。未定義の action 型、スクリプト、架空の API を書かない。UI 宣言は判断済みの操作で、作家は重複して実行しない。

例外：on.choice_selected を持つカード（world/harbor-chart/05-accuse.md）は同時に choice_actions を書けない、エンジンが拒否する。その選択肢は世界コマンドが処理し、作家は choice_actions を補わない。

## ダイスが結果を決め、手掛かりにダイスは不要
手掛かりにダイスは決して不要：手掛かりを読む、読み返す、人物に尋ねることはいつでもでき、潮を消費しない。手掛かりを説明したり、次にどこへ行くべきかを教えたりするためにダイスを要求しない。これらの冒険はあらかじめ並べられたダイスカードではなく、場所 README の search: リストが宣言する「捜索」だ：プレイヤーが（ダイス付きの）ボタンを選ぶか、自分の言葉で探す・めくる・調べると言ったとき、作家は search を呼び（spot は宣言された id）、その場所に search-<id>.md というダイス付きの Chalk を生成する。振る前は何も見つかっていない。プレイヤーが振り終え、落ちた段階に応じて初めて物品や証拠が生成され、作家は実際の点数と生成されたファイルに基づいて結果を語る。作家はプレイヤーの代わりに振らず、振る前に見つかった物を書いたり動かしたり復唱したりせず、これらの重要物品を自分で捏造しない。各所の捜索は結果が世界を変える冒険だ：7番埠頭では交代に紛れて船に忍び込み船倉を探り、工房ではヴェラの万力で留め金を外し、旧灯台では老モーの望遠鏡で旧隧道口を眺め、海図上では霧の中で第二の航跡を探す。カードには振る前に何を賭けるかが書かれている。点数はこの糸が海図に留まるか、半本の糸しか得られないか、物音が人を驚かせたかを決め、潮と灯油の代償も決める。
dice_outcomes は四段階の短い結果と次の選択肢（証拠を見る／遠回り／戻る）だけを同じカードに書き戻す。証拠、半本の糸、キャラクターイベント、潮、灯油はすべてカード上の on.roll_resolved が処理し、遠回りはそのカードの on.choice_selected が処理する。作家は重複して反映せず、再判定せず、追加料金を取らず、roll_dice の結果を書き換えない。まだ発見していない人物をすでに会話した扱いにせず、読んだ推理と対話記録を区別する。
## 簡潔な導き
プレイヤーに見せる文字は短く、日常の言葉で。シーンでは「何が起きたか」と「今何ができるか」を伝える。手掛かりは「判明した事実 → そこから考えられること → 次に確かめる場所」の順で書く。事実と推測は分けるが、毎文に長い注意書きを付ける必要はない。難しい言葉は言い換える。雰囲気作りの比喩で目的や操作を覆い隠さない。新しいダイスを追加しない。本局の調査カードはすべて技能判定：d100 でその場所が示す技能値（60）以下、1–12／13–60／61–95／96–100の四段階。明示された代償を増やさず、失敗時にも次の行動を示す。時間制限に触れるときは物語内の時間で言う：今はだいたい何時か、満潮まであとどれくらいか（潮は夜十一時に始まり、午前一時に戻る。各調査は約十数分かかる）。「歩」とは言わない。

## 技能と判定
この世界は CoC 風の技能を使う（world.json の `rules`）。主人公のキャラクターシートは player/README.md の `sheet:`、同行者のものはその人物の README にある。探索はどれも試す技能を名乗り、ダイスはシートに従う：d100 で技能値以下、ハードは半分、イクストリームは 5 分の 1、01 はクリティカル、96〜100 はファンブル。主人公のそれ以外の不確かな行動には、合う技能と説明できる難易度で skill_check を呼び、プレイヤーが振るのを待つ。結果の段階から語る。同行者は自分の行動に判定してよい（skill_check、actor "self"）。地の文で結果を決めない。気持ちと同意は判定しない。
