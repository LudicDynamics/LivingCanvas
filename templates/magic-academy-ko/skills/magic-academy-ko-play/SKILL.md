# 세계 운영 규칙

이것은 실제로 파일을 갱신하는 플레이다. 대사만으로 성공을 선언하지 않는다. 먼저 현재 행동 원본, 위치와 상위 리드미, 의도, 관련 아이템, 인물 기억, 제공된 방문 기록을 읽는다. 리드미는 장소와 알려진 출구를 제공하고, 초크는 현재 선택지와 생성 의도를 제공하며, 이 스킬은 세계 불변식을 담는다. 의도는 작가에 대한 지시이지 새로운 엔진 명령이 아니다.

## 언어와 지식
내레이션, 제목, 선택지, 생성 프롬프트는 영어로 쓴다. 파일 이름, 디렉터리, 캐릭터 ID는 소문자 영어 케밥 케이스로 고정하며, 표시 이름을 경로로 쓰지 않는다. 예: world/harbor-chart/beyond-the-fog/lighthouse-road/README.md, player/introduction-letter.md, characters/nanami/memory.md. README.md, SKILL.md, world.json, preset.json 및 기존 에셋 경로를 보존한다. 새 초크에는 안정적인 영어 경로와 영어 제목 및 본문을 부여한다. 캐릭터는 자신이 목격하거나 들은 것만 안다. 플레이어가 마주치지 않은 비밀을 에필로그의 기억으로 만들지 않는다.

## 행동 완료
하나의 선택은 하나의 구체적 변화를 반환한다. 획득한 아이템은 이동되며, 읽기만으로는 이동하지 않는다. 리드미는 이동하지 않는다. 캐릭터를 도구로 취급하지 않는다. 제출은 참조이지 소비가 아니다. 플레이어가 언급한 아이템의 경로와 의미를 확인한다. 선택지를 누르는 것만으로 말하지 않은 생각이나 계획을 대필하지 않는다. 초안 대필은 플레이어가 요청하고 확인했을 때만 수행한다.

실행 전에 생성, 갱신, 최종 릴리스할 파일을 나열한다. 하나의 텍스트를 완전히 작성한 후 모든 파일을 다시 읽는다. 조건이 충족되지 않거나 도구가 실패하면 누락된 항목을 보고하고 릴리스하지 않는다. 기존 결과를 읽어 누락된 부분만 수정 재시도한다. 더블 클릭 시 중복 보상이나 소비가 없어야 한다. 새 세계 상태 파일은 생성되지 않으며, 사실은 내용과 status.data에 평면적으로 저장된다.

## 판정
판정 전에 같은 초크에 목표, 필요한 아이템, 불확실성 이유, 공식, 성공 기준, 확률, 일반 및 대성공, 실패와 희귀한 피해, 굴리지 않을 선택지를 제시한다. roll_dice는 여러 줄 YAML이어야 한다. 인라인 {type:...}은 결과 재작성을 지원하지 않는다. expect는 인용되어야 한다. 제출과 입장은 roll_dice를 호출하지 않는다. 플레이어는 조건을 본 후 굴린다. 변경된 조건은 재시도를 유도한다. 주사위로 사실의 진위나 동의를 결정하지 않는다. 기존 결과를 지우거나 무료 재굴림을 제공하지 않는다.

## 새 위치 생성 시
상위 리드미와 입장 초크의 명시적 범위 내에 자식 폴더를 하나만 생성한다. 평범한 방을 조사하는 것만으로 마을을 확장하지 않는다. 먼저 입장의 가시적 문구를 작성한 후 리드미, 의미 있는 아이템 두 개, 행동 초크, 상위로 돌아가는 문을 작성한다. 필요 시 이름, 역할, 목격 가능한 대사를 포함한 새 거주자 노트를 하나 도입한다. 등록되지 않은 캐릭터를 위한 대화 버튼은 없다. 작가 역할이 그러한 만남을 연기한다.

리드미의 존재 자체를 완성으로 간주하지 않는다. 하위 리드미, 두 아이템, 초크, 출구를 확인한다. 빠진 부분은 같은 위치에서 복구한다. 재방문 시 장소나 인물을 다시 무작위화하지 않는다. 텍스트 완료 후 실제 조명, 사물, 시간에 맞는 배경을 위해 generate_image를 한 번 호출한다. 반환된 유효 자산은 리드미 bg에 기록한다. 실패는 텍스트 실패로 간주하지 않는다. 누락된 이미지를 보고하고 자동 재시도하지 않는다. 새 이미지와 충돌하는 경우 이전 bgVideo를 제거한다. 플레이 가능한 텍스트는 미리 사용할 수 있다. 시간 1–2은 예산이며 속도 약속이 아니다.

## 짧은 조합 수업
입구 → 도감 → 조합 → 대가 제시 → 이름 붙이기와 명시적 시전 → 짧은 결과. 전체 학기 생성은 하지 않는다. 재료 소유는 실제 아이템으로 확인한다. 제안 중에는 소모하지 않는다. 동사에 대해 동의어와 일관된 창의성을 허용한다.

player/spell-draft.md 파일은 플레이어의 말을 저장한다. 초안을 world/spell-atlas/03-casting-terms.md 파일로 읽어 들이며 아이템 경로, 가능한 것, 불가능한 것, 대가, 그리고 그 조합을 고른 이유를 담는다. "이 조건으로 이름 붙이고 시전", "수정", "그만두기" 선택지를 제공한다. 정해지지 않은 이름을 묻는다. 플레이어의 동의가 있을 때만 실행한다. 짧은 역할극 해결을 위해 아이템 조합을 인용할 수 있으며, 주사위는 필수가 아니다.

후보 대가에는 별의 조각이 다음 밤까지 잠시 빛을 쉬게 하는 것이 포함된다. 사전 동의 없이 기억, 목소리, 이름을 영구히 잃지 않는다. 다른 대가를 고르기 전에 범위를 합의한다. 불확실한 시전에만 선택적 사전 선언 판정을 붙인다. 공식, 기준값, 모든 결과 확률, 보통/대성공, 실패/희귀한 피해를 표시한 뒤 플레이어의 주사위 입력을 기다린다. 조용한 수치 추가는 없다.

"열다" + 별의 조각이 공간을 열기로 합의했다면 world/spell-atlas/star-chart-room, changed-space.md, cost-trace.md, 01-my-spell.md, return-gate.md에 대한 리드미를 생성하고, 천문대 입구를 배치한다. "비추다" + 손거울이 휴대용 별지도에 합의했다면 world/spell-atlas/palm-stars와 player/named-star-chart.md.에 같은 구조를 만든다. 이것은 거울에 별을 비추지만 입구는 없다. 모든 성공을 같은 입구로 합치지 않는다. 의미와 대가에서 짧은 대안을 하나 만들고, 그 동사의 결과 폴더에 둔다("열다" 주문은 모두 star-chart-room, "비추다" 주문은 모두 palm-stars). 폴더 id는 그대로 두고, 제목은 실제로 바뀐 것을 따른다. 01-my-spell.md에는 반드시 "밤의 도서관으로 가져가기"(choice_actions kind enter, target map)를 둔다.

시전 후에만 실제로 사용한 아이템에 대가를 적용하고, 실행 사실과 결과 위치를 같은 초안에 기록한다. 이중 실행은 없다. 필요하면 결과에 어울리는 배경 이미지를 생성한다. 세라피나는 플레이어가 이름 붙인 단어를 인용하며 변화를 네 앞에서 보여준다.

## 결말
이 세계는 `semi`이며 결말은 세 개, 엔진만 내린다:
- `opened-door`(네가 연 문): world/spell-atlas/star-chart-room/01-my-spell.md가 생긴 뒤 플레이어가 밤의 도서관(`map`)으로 돌아온다(트리거 back-to-the-library → command/lesson-ends.yaml).
- `kept-stars`(손바닥 위의 별): world/spell-atlas/palm-stars/01-my-spell.md가 생긴 뒤 같은 귀환.
- `unnamed`(빈 명찰): 플레이어가 시전 없이 수업을 끝내기로 분명히 정하면 작가는 `trigger_keyword({ id: "leave-without-a-spell" })`를 호출한다(command/leave-unnamed.yaml. 이미 시전한 주문이 있으면 그 결말). 대가를 묻기, 수정, "아직"은 해당하지 않는다.
본문에서 결말을 선언하지 않고, 시전을 재촉하지 않는다. 결말 뒤에는 대화만 남는다.

## 확정 행동과 작가의 분리 (현재)
choice_actions는 choice.options의 영어 ID와 일치하는 구현된 UI 행동 선언이다. read(paths), take(paths), stage(paths), enter(target), character(character), reply(text), writer(prompt 선택)만 사용한다. 읽기, 이동, 장소로 돌아가기, 재료 준비, 짧은 주사위 표시는 작가를 발동하지 않는다. stage는 재료만 확인하며 제출이나 실행은 없다. writer는 생성, 자유 RP, 미확정 약속, 전략에만 사용한다. 인물 질문은 대화를 열며, 요청 없이 대사를 보내지 않는다.
새 초크도 choice id와 choice_actions를 받는다. 읽기와 돌아가기는 모호한 작가 선택이 아니다. 미래의 재료 경로를 이미 존재하는 읽기로 선언하지 않는다. 정의되지 않은 행동 유형, 스크립트, 가짜 API는 없다. UI 선언은 결정된 작업이며, 작가는 이중 실행하지 않는다.

## 명확한 안내
플레이어에게 보이는 텍스트는 짧고 일상적인 단어를 쓴다. 장면은 "무슨 일이 있었는지"와 "지금 무엇을 할 수 있는지"를 전한다. 단서는 "알려진 사실 → 가능한 추론 → 다음에 확인할 장소" 순서로 보여준다. 사실과 추측을 구분하고, 매 문장에 긴 단서 조항을 붙이지 않는다. 어려운 단어를 바꾼다. 분위기 은유를 쓰되 목표나 행동을 숨기지 않는다. 새 주사위는 1d10, 2d10, 1d100뿐이다. 현재 조사 카드는 2d10, 성공 ≥ 11, 단계 2–4/5–10/11–17/18–20이다. 알려진 대가를 늘리지 않으며, 실패 후에도 다음 행동을 보여준다.

## 기능과 판정
이 세계는 D&D 풍 기능을 쓴다(world.json의 `rules`). 주인공의 캐릭터 시트는 player/README.md의 `sheet:`(능력 수정치와 숙련 기능), 동료의 시트는 그 인물의 README에 있다. 판정은 d20 + 기능 수정치로 DC(쉬움 10, 보통 12, 어려움 15, 매우 어려움 20)에 도전하고, 상황이 주면 이점이나 불리로 굴린다. 내추럴 20은 반드시 성공, 내추럴 1은 반드시 실패. 주인공이 불확실한 일을 시도하면 알맞은 기능과 DC로 skill_check를 부르고, 플레이어가 굴릴 때까지 멈춘다. 판정된 단계에 따라 서술한다. 동료는 자기 행동에 판정할 수 있다(skill_check, actor "self"). 본문에서 결과를 정하지 않는다. 감정, 약속, 동의는 판정하지 않는다.
