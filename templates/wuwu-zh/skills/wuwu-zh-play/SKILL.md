# 世界执行规则

这是真正更新文件的游戏。不要只靠台词宣布成功。先阅读本次行动的来源、当前所在地及其上级 README、其中的 intent、相关实物、人物记忆，以及提供的既往访问记录。README 记载地点与已知出口，Chalk 记载当前的选择与具体的生成意图，本 skill 记载世界的不变条件。intent 不是新的引擎命令，而是给作家的指示。

## 语言与知识
叙述、title、选项与生成指示均使用简体中文。文件名、目录名与人物 ID 固定为小写 ASCII kebab-case，不要把显示名称用作路径。例：world/harbor-chart/05-accuse.md、player/decoy-ship.md、characters/vera/memory.md。保留 README.md、SKILL.md、world.json、preset.json 以及已有的素材路径。新建的 Chalk 也要给出稳定的 ASCII path，title 与正文使用简体中文。人物只知道自己目击或听说的事实。不要把玩家没有接触过的秘密写成后日谈里的回忆。

## 行动的完成
每个选择返回一项具体的变化。被说要拿走的实物用 move，只是阅读则不移动。README 不移动。不要把人物当作道具。提交是引用，不是消耗。确认实物的路径，以及玩家所说的含义。不要仅因按下了选项，就代写玩家没说出口的推理、计划或告白。只有在玩家委托并确认了内容时，才代写草稿。

执行之前，自己先列出这次行动要创建的文件、要更新的文件和最后发放的物品。不要写了一段文字就中途结束，要把所有文件重读一遍。条件未满足或工具失败时，说明缺少什么，不发放奖励物。重试时先读已有结果，只修补缺少的部分。不要因为双击而重复发放奖励或重复消耗。不要创建新的世界状态文件，而是用相应物品的正文和 status.data 中的扁平值记录事实。

## 判定
本局不新增判定卡；以下是已有骰卡遵守的格式。
判定之前，在同一张 Chalk 中写明：对象、所需物品、为什么不确定、公式、成功条件、概率、普通成功、大成功、失败与小概率的实际损害，以及不掷骰返回的选项。roll_dice 必须写成多行 YAML。行内的 {type:...} 不支持回写结果。expect 要加引号。仅提交或进入时不调用 roll_dice。由玩家看过显示的条件后自己掷骰。条件改变时要重新出示。不要用骰子决定事实真伪或对方是否同意。不要删掉已有的 result 来免费重掷。

## 这是封闭的一局：时限与三个结局
这一局有时限、有结局。world.json 的 mode 是 closed。潮位卡 world/tide.md 的 status.data.left 是剩下的步数，开局为 8。只有引擎的 tick 能改它；作家不要手动改这张卡，也不要在叙述里替潮水加减步数。

潮水怎么涨（全部由各调查骰卡上的 on.roll_resolved 自动执行，作家不重复执行）：
- 每掷一次调查骰（7号码头、旧灯塔、工坊三处的搜查 search-scene.md，以及海图上的决定性搜查 world/harbor-chart/search-fog.md）：-1（command/tide-step.yaml）。大成功（1–12）查得快，这一掷不耗潮水。
- 落在 96–100：再 -1（command/tide-surge.yaml）。
- 走一次“绕远路”（见下）：-1（command/long-way-*.yaml）。
- 每张骰卡只能掷一次。对话、阅读、走动都不耗潮水。

证据由点数决定，由引擎发放，并在指认卡上打✓（没钉上的线会留一行✗）：
- 13–60：证据进包，打✓。1–12：同上，且不耗潮水。
- 61–95：只拿到“半条线”（player/decoy-ship-half.md、customs-tunnel-half.md、ledger-page-half.md、second-wake-half.md），不打✓。半条线不能用来指认，也不会自己变成证据。
- 96–100：什么也没拿到，还会落一个角色事件（7号码头：银鸢撞见你；旧灯塔：老莫的望远镜摔裂；工坊：扣件的销子崩断，薇拉看见了）。海图上的 96–100 见下面的被雾吞。
- 没钉上（61–100）时，同一地点的“绕远路”卡会打开（world/harbor-chart/seventh-berth/05-long-way.md、old-lighthouse/05-long-way.md、workshop/05-long-way.md、world/harbor-chart/06-long-way.md）。选它由引擎发放完整证据、打✓、潮水 -1；每张只能走一次。失败从不走进死路，只是更费潮水。
各张卡对应的证据：
- 7号码头 → player/decoy-ship.md（无人船是诱饵）
- 旧灯塔 → player/customs-tunnel.md（熄灯的十二分钟对着旧海关隧道出口）
- 工坊 → player/ledger-page.md（扣件记在领主家的账簿上）
- 海图决定性判定 → player/second-wake.md（雾里的第二道航迹）
作家不要另造、补发、复制这些证据或半条线文件，不要把半条线改写成证据，也不要把它们改名或移出 player/。角色事件已经发生：被撞见的银鸢、摔了望远镜的老莫、弄断销子后的薇拉，在玩家当面说清或道歉之前，说话会带着这件事；不要替玩家抹掉它，也不要让它挡住“绕远路”（那是引擎的确定操作）。

灯油：旧灯塔只有一份，由“借一份灯油”按钮确定地移到 player/lamp-oil.md。任何调查骰落在 96–100 时，若身上带着灯油，它会被烧光，变成 player/empty-oil-flask.md（command/burn-lamp-oil.yaml）。作家不要补发灯油，也不要把空瓶重新灌满。

三个结局（只有这三个，不许发明第四个）：
- 揭穿（exposed）：四件证据都在 player/ 时，在 world/harbor-chart/05-accuse.md 选“在海图上指认”，引擎跑 command/accuse.yaml 执行 end。四条线没钉齐时，指认卡只显示“对照海图”，只会在卡上留一句还差线的提示，不结束。
- 追丢（lost）：潮位降到 0 时，引擎的 tick 自动结束这一局。
- 被雾吞（swallowed）：海图上的决定性判定落在 96–100，而手里没有能点的灯油（灯油已烧成空瓶，或从没借过）时，引擎跑 command/fog-swallows.yaml 执行 end。手里还有灯油时，落在 96–100 只会把油烧光，不会被吞。伤势归零时，引擎也会跑 command/hurt-out.yaml 到达被雾吞（见下面的伤势）。

结局只由引擎的 end（或 tick 归零）触发。作家绝不能用叙述宣布结局、写“这一局结束了”，也不能在证据不齐时让任何人“相信”指认。结局到达后世界进入尾声：只剩对话。可以和薇拉、银鸢、老莫说话，回顾这一夜；不要再移动物品、生成卡片、掷骰或改写世界。玩家想再玩，引导他们用“再来一局”。

## 伤势（隐藏）
这一局没有敌人。伤来自地方和意外：雾里湿滑的礁石、回涨的潮水、旧海关隧道、7号码头的舷梯、灯塔湿滑的楼梯、场面僵住时被人推搡。玩家的伤势是一个隐藏状态（player/README.md 的 `states: hp`），面板只用文字说（毫发无伤 / 受了伤 / 伤得很重 / 奄奄一息）。
- 只有骰子和命令能改它：各处调查骰的 96–100 档带 `harm`（海图上的决定性判定最重，旧灯塔次之，7号码头和工坊轻些）。最重的一下也不会从毫发无伤直接要命，只会让人伤得很重。作家绝不改 hp，不自己加伤、治伤，也不写任何数字。用文字描述伤，跟着骰子档位和面板说。
- 伤积得太重，引擎会结束这一局（world.json 触发器 too-hurt → command/hurt-out.yaml → 被雾吞）。不要自己宣布，也不要用数字提醒玩家。

## 可骰可不骰的骰子与事件
旧灯塔的「趁老莫不注意，翻他的日志」（旧灯塔 README 声明的搜查 peek-logbook，掷骰卡是 world/harbor-chart/old-lighthouse/search-peek-logbook.md）是可选的：不扣潮水，也不是结局所需的证据。骰完由引擎落一个事件——中了是日志上的物品事件（夹层里的铅笔字，三短一长的灯号），没中是落在老莫身上的角色事件（他看见了）。大成功时玩家还会拿到 player/lamp-signal.md（那行字的抄件，不是指认用的证据）。事件已经发生，不要再叙述一遍、不要改写结果；接下来的戏要承接它：被看见之后，老莫防着玩家，直到玩家赔了不是。不要自己发明别的事件结果。

## 雾坞镇的真相（固定）
无人船是诱饵。领主家的账簿、旧海关隧道和熄灯的十二分钟连在一起。老莫不知道追踪船的存在。不要把薇拉的舵扣件和银鸢的空箱，轻易变成犯人的自白。点数决定玩家当场拿到多少证据、付出多少潮水和灯油、谁被惊动，不改变真相。

## 不生成新地点
这是封闭的一局，地图就是港务所、港口海图、7号码头、工坊和旧灯塔这几处。不要在 world/harbor-chart/beyond-the-fog/、tidal-approach/ 或任何地方生成新的场景、道路、城镇或新住民，不创建介绍信，不追加新的判定卡或新的 roll_dice。雾的另一边不会打开：第二艘船要么被指认、要么被追丢、要么你被雾吞掉。玩家想“走进雾里”时，用已有的决定性判定卡回应，并说明它的代价。

## 不填表、不答题
推进剧情从不靠填表或答题：不要让玩家摆材料、提交推理、往格子里放东西，也不要让玩家回答问题才能往下走。world/harbor-chart/02-two-wakes.md 只是找薇拉商量的地方：她用自己的口吻聊玩家包里真有的证据、它们说明什么、下一处该去哪张骰卡。不发放证据，不打✓，不宣布结局，不耗潮水。压力来自潮水和人：银鸢、老莫、薇拉会因为玩家惊动了他们而逼玩家当面说清。

## 结局之后的复盘
结局之后，玩家会有一次复盘（关于那一夜真相的四个问题）。游戏过程中不要把答案告诉玩家，也不要让角色把真相说破；让证据、潮水和人物的施压把玩家推近真相。

## 确定操作与作家的分离（现行）
choice_actions 是已实现的 UI 操作声明，对应 choice.options 中的 ASCII id。只使用 read(paths)、take(paths)、enter(target)、character(character)、reply(text)、writer(prompt 可选)、search(spot)。阅读、搬运、返回已有场景、简短显示骰子结果时，不启动作家。只有在自由 RP、执行尚未确定的约定或计划时，才使用 writer。询问人物时用 character 打开对话，不擅自发送台词。
新生成的 Chalk 也要为每个选项加上 id 和 choice_actions。不要把阅读或返程做成含糊的 writer 选项。不要把未来的素材路径声明为已有的 read。不要写未定义的 action 类型、脚本或虚构的 API。UI 声明是已判断好的操作，作家不重复执行。

例外：带 on.choice_selected 的卡（world/harbor-chart/05-accuse.md）不能同时写 choice_actions，引擎会拒绝；它的选项由世界命令处理，作家不要给它补 choice_actions。

## 骰子决定结果，提示不需要骰子
提示永远不需要掷骰：读线索、重读线索、问人物，随时都可以做，不耗潮水。不要为了解释线索或告诉玩家下一步去哪而要求掷骰。这些冒险不是预先摆好的骰子卡，而是地点 README 的 search: 列表里声明的“搜查”：玩家选带（掷骰）的按钮，或用自己的话说要搜、翻、查时，作家调用 search（spot 用声明的 id），在该地点生成 search-<id>.md 这张带骰子的 Chalk。掷骰前什么都还没找到；玩家掷完，按落在的档次才生成物品或证据，作家再根据实际点数和生成的文件讲述结果。作家不替玩家掷骰，不在掷骰前写出、移动或复述找到的东西，也不自己编造这些关键物品。每处搜查是一次结果会改变世界的冒险：7号码头趁换岗溜上船翻货舱，工坊在薇拉的台钳上拆开扣件，旧灯塔用老莫的望远镜看旧隧道口，海图上在雾里找第二道航迹。卡上掷骰前就写明赌的是什么；点数决定这条线钉上、只拿到半条线，还是惊动了人，并决定潮水和灯油的代价。
dice_outcomes 只把四档的简短结果和下一步选项（看证据 / 绕远路 / 返回）写回同一张卡；证据、半条线、角色事件、潮水和灯油全部由卡上的 on.roll_resolved 处理，绕远路由那张卡的 on.choice_selected 处理。作家不重复反映、不重新判定、不追加收费、不改写 roll_dice 的结果。不要把尚未发现的人物当作已经交谈过，要区分读到的推理与对话记录。
## 简明的引导
给玩家看的文字要简短，用日常用语。场景中要传达“发生了什么”和“现在能做什么”。线索按“查明的事实 → 由此能想到的事 → 下一个要确认的地点”的顺序写。事实与推测要分开，但不必每句都附上长长的注意事项。难懂的词要换个说法。不要用营造气氛的比喻掩盖目的或操作。不新增骰子。本局的调查卡都是技能检定：d100 小于等于该处写明的技能值（60），分1–12/13–60/61–95/96–100四档。不增加已明示的代价，失败时也要给出下一步行动。提到时限时，用故事里的时间说：现在大约几点、离涨潮还有多久（潮水夜里十一点开始、凌晨一点回涨，每次调查约耗十几分钟），不要说“步”。

## 技能与检定
这个世界用类 CoC 的技能（world.json 的 `rules`）。主角的角色卡是 player/README.md 的 `sheet:`，同伴的在各自的角色 README 里。每个搜查都写明检定哪项技能，骰子按角色卡：d100 小于等于技能值，困难取一半，极难取五分之一，01 大成功，96–100 大失败。主角其他没有把握的行动，用合适的技能和说得出理由的难度调用 skill_check，然后停下等玩家掷；按结算出的档位叙述。同伴可以为自己的行动检定（skill_check，actor "self"）。不要在正文里替骰子决定结果；感情与同意从不检定。
