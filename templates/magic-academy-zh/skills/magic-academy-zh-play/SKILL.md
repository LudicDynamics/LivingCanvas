# 世界运行规则

这是一个真正会更新文件的游戏。不能只靠台词宣布成功。先读取本次行动的来源、当前位置与上级 README、其中的 intent、相关的实物、人物的记忆，以及提供的已访问记录。README 负责地点和已知出口，Chalk 负责当前的选择与具体的生成意图，本 skill 负责世界的不变条件。intent 不是新的引擎命令，而是给作家的指示。

## 语言与知识
叙述、title、选项和生成指示都用简体中文。文件名、目录名和人物 ID 固定使用小写 ASCII 的 kebab-case，不要把显示名称当作路径。例：world/harbor-chart/beyond-the-fog/lighthouse-road/README.md、player/introduction-letter.md、characters/nanami/memory.md。保留 README.md、SKILL.md、world.json、preset.json 以及已有的素材路径。新的 Chalk 也要给出稳定的 ASCII path，title 和正文用简体中文。人物只知道自己亲眼目睹或听人转述的事实。不要把玩家没有见过的秘密写成后日谈里的回忆。

## 行动的完成
一个选择只回应一个具体的变化。玩家说要拿走的实物用 move；只是阅读则不移动。README 不移动。不要把人物当作道具。提交是引用，不是消耗。确认实物的路径和玩家所说的含义。不要因为玩家按了某个选项，就替玩家写出没说出口的推理、计划或告白。只有在玩家要求并确认内容后，才代写草稿。

执行之前，先自己列出这次行动要创建的文件、要更新的文件以及最终的解锁物。不要写完一段文字就结束，要把所有文件重读一遍。条件未满足或工具失败时，说明缺了什么，不发放解锁物。重试时先读已有结果，只修补缺失部分。连点两次也不能重复发放奖励或重复消耗。不要新建世界状态文件，事实记录在相应物品的正文和 status.data 的扁平值里。

## 检定
检定之前，在同一张 Chalk 里写明：对象、所需物品、为什么不确定、公式、成功条件、概率、普通成功、大成功、失败与小概率的实际损害，以及不掷骰直接返回的选项。roll_dice 必须写成多行 YAML。行内的 {type:...} 不支持回写结果。expect 要加引号。仅仅提交或进入时不调用 roll_dice。由玩家看过展示的条件后自己掷骰。条件变了就重新展示。不要用骰子决定事实真假或对方是否同意。不要删除已有的 result 免费重掷。

## 生成新地点时
只在上级 README 和入口 Chalk 明确给出的范围内，创建一个子文件夹。只是调查普通的室内，不要凭空增加城镇。先写入口处能看到的一句话，再写 README、两件有意义的物品、带行动的 Chalk，以及返回上级的 gate。需要时可以把一件物品写成介绍新居民的 note，留下名字、职业和能亲眼见到的话语；不要为未登记的 characterId 做对话按钮，由作家来演绎这次相遇。

不要因为 README 存在就当作完成。确认子 README、两件物品、Chalk 和返回口都在，缺了就在同一地点修补。重访时不重新抽取地点或人物。文字完成后只调用一次 generate_image，要求背景与实际地点的光线、物品和时刻一致。只把返回的真实 asset 写进 README 的 bg。图片失败不算文字失败；失败时告知图片还没到，不自动重试。旧的 bgVideo 与新图矛盾时就去掉。已完成的文字可以先玩。1–2 分钟是演出预算，不是生成速度的承诺。

## 组合的小课堂
入口 → 图谱 → 组合 → 展示代价 → 命名并明确施法 → 简短结果。不要做成一整个学期。用实物确认素材的持有情况。提议期间不消耗。接受动词的换一种说法以及合情合理的创意。

player/spell-draft.md 保存玩家的原话。读完草稿后，在 world/spell-atlas/03-casting-terms.md 中写明：所用物品的路径、能做到什么、做不到什么、代价，以及为什么是这个组合。放上「命名并按此条件施法」「修改」「放弃」三个选项。还没决定的名字要询问。只执行本人同意的条件。需要时可以引用物品组合，用简短的角色扮演来解决，骰子不是必需的。

候选代价是：星星碎片要让光芒休息到下一个夜晚，这是看得见的暂时消耗。不要擅自让记忆、声音、名字永久丧失。如果玩家想要别的代价，先商定范围。只有结果不确定的施法，才另外做可选的检定预告：展示公式、阈值、所有结果的概率、普通成功与大成功、失败与小概率的损害，等待本人操作掷骰。不要悄悄加数值。

如果商定用「开启」＋星星碎片打开空间，就可以生成 world/spell-atlas/star-chart-room 的 README、changed-space.md、cost-trace.md、01-my-spell.md、return-gate.md，并放置通往天文台的入口。如果商定用「映照」＋手镜做成可随身携带的星图，就生成 world/spell-atlas/palm-stars 的同样结构以及 player/named-star-chart.md。这一种会让星星映在镜中，但进不了天文台。不要让所有成功都汇聚到同一个入口。其他方案则根据含义和代价做出一个简短结果。

只有在施法之后，才把代价反映到实际用到的物品上，并在同一份草稿里记录已执行的事实和结果所在的位置。不要重复执行。需要时生成一张符合结果的背景图。塞拉菲娜会引用玩家起的名字，当着你的面展示改变了什么。

## 确定操作与作家的分离（现行）
choice_actions 是已实现的 UI 操作声明，对应 choice.options 中的 ASCII id。只使用 read(paths)、take(paths)、stage(paths)、enter(target)、character(character)、reply(text)、writer(prompt 可选)。阅读、搬运、回到已有场景、摆放材料、简短显示骰子结果时，不启动作家。stage 只是确认材料，不是提交或执行。只有生成、自由角色扮演、执行未确定的约定或计划时，才使用 writer。向人物提问时用 character 打开对话，不要擅自发送台词。
新生成的 Chalk 也要给每个选项加上 id 和 choice_actions。不要把阅读或返回做成含糊的 writer 选项。不要把将来才有的素材路径声明为已存在的 read。不要写未定义的 action 类型、脚本或虚构的 API。UI 声明是已经判断好的操作，作家不重复执行。

## 简明的引导
面向玩家的文字要简短，用日常用语。在场景里说明「发生了什么」和「现在能做什么」。线索按「已知事实 → 由此可推想的事 → 下一步去确认的地方」的顺序写。事实与推测要分开，但不必每句都加长长的注释。难懂的词换个说法。不要用氛围化的比喻掩盖目的或操作。新的骰子只用 1d10、2d10、1d100。本次调查卡为 2d10，成功 ≥ 11，分 2–4/5–10/11–17/18–20 四档。不要增加已说明的代价，即使失败也要给出下一步行动。

## 技能与检定
这个世界用类 D&D 的技能（world.json 的 `rules`）。主角的角色卡是 player/README.md 的 `sheet:`（属性调整值与熟练技能），同伴的在各自的角色 README 里。检定是 d20 + 技能调整值对抗 DC（简单 10、普通 12、困难 15、极难 20），情境给出时按优势或劣势掷；天然 20 必定成功，天然 1 必定失败。主角尝试没有把握的事时，用合适的技能和 DC 调用 skill_check，然后停下等玩家掷；按结算出的档位叙述。同伴可以为自己的行动检定（skill_check，actor "self"）。不要在正文里替骰子决定结果；感情、承诺与同意从不检定。
