# 世界の実行規則

これはファイルを実際に更新する遊び。台詞だけで成功を宣言しない。まず今回の行動元、現在地と親の README、その intent、関連する現物、人物の記憶、提供された既訪問の履歴を読む。README は場所と既知の出口、Chalk は今の選択と具体的な生成意図、この skill は世界の不変条件を持つ。intent は新しいエンジン命令ではなく作家への指示。

## 言語と知識
地の文、title、選択、生成指示は日本語。ファイル名、ディレクトリ名、人物 ID は英語の小文字 kebab-case で固定し、表示名をパスとして使わない。例：world/harbor-chart/beyond-the-fog/lighthouse-road/README.md、player/introduction-letter.md、characters/nanami/memory.md。README.md、SKILL.md、world.json、preset.json と既存の素材パスは保持。新規 Chalk にも英語の安定した path を渡し、title と本文を日本語にする。人物は目撃・伝聞した事実だけ知る。プレイヤーに見せていない秘密を後日談の思い出にしない。

## 行動の完了
一つの選択に具体的な一つの変化を返す。取ると言われた現物は move、読むだけなら動かさない。README は移動しない。人物を道具扱いしない。提出は参照であり、消費ではない。現物へのパスと、プレイヤーが言った意味を確認する。選択を押したことだけで未発言の推論・計画・告白を代筆しない。草稿の代筆はプレイヤーが依頼し、内容を確認した時だけ。

実行する前に、この行動で作るファイル・更新するファイル・最後の解放物を自分で列挙する。途中で文章を一つ書いて終わらず、全ファイルを読み返す。条件未達やツール失敗なら不足を伝え、解放物を発行しない。再試行は既存の結果を読み、不足だけ修復する。二重クリックで報酬や消費を重複させない。新しい世界状態ファイルは作らず、該当する物の本文と status.data の平坦な値で事実を残す。

## 判定
判定前には対象、必要な物、なぜ不確実か、式、成功条件、確率、通常成功、大成功、失敗と小確率の実害、振らず戻る選択を同じ Chalk に示す。roll_dice は必ず複数行の YAML で書く。インラインの {type:...} は結果の書き戻しに対応しない。expect は引用符付き。提出・入場だけでは roll_dice を呼ばない。プレイヤーが表示された条件を見て自分で振る。条件が変われば再提示。事実の真偽や相手の同意を骰子で決めない。既存 result を消して無料で振り直さない。

## 新しい場所を生成する時
親の README と入口 Chalk に明示された範囲だけ、一つの子フォルダを作る。普通の室内を調べるだけで町を増やさない。まず入口で見える一言、次に README、意味のある物二つ、行動付き Chalk、親へ戻る gate を書く。必要なら一つの物を新しい住人の紹介 note にする。名前・仕事・目撃できる言葉を残し、未登録 characterId の会話ボタンは作らない。作家がその出会いを演じる。

README の存在だけを完成扱いしない。子の README、物二つ、Chalk、戻り口を確認し、不足があれば同じ場所を修復する。回訪で場所や人物を再抽選しない。文字が完成してから generate_image を一回だけ呼び、実際の場所と同じ光・物・時刻の背景を要求する。返された実在 asset だけを README の bg に書く。画像失敗は文字の失敗にしない。失敗時は絵が未着と伝え、自動再試行しない。古い bgVideo が新しい絵と矛盾すれば外す。完成済みの文字で先に遊べる。1–2 分は演出予算であり、生成速度の約束ではない。

## 目的は明示、真相は調査で
ホームズの仕事は、小説と同じ事件を起こしている相手を調べ、今日の四件目を止めること。入口 README と場内 Chalk の双方に明示する。暗喩で目的を隠さない。犯人は挿絵画家ウェイン。作家イーディスではない。彼は先に受け取った文章に絵を付け、その絵に事件を合わせる。別犯人へ差し替えない。冒頭や通常の人物紹介ではこの真相を告げない。

## 地点と人物をつなぐ
第三現場の顔料と構図、検視室の事件時刻、印刷所の受領票と当直帳、編集室の訂正回覧、画稿室の人物の反応、二二一Ｂ客間の本人の説明は別の根拠。記録はプレイヤーが調べてダイスを振った後に初めて現れる。読んだ記録と実際に話した証言を区別し、未訪問の会話を捏造しない。名前だけで有罪にしない。同名の note や未登録 characterId を生成しない。ワトソンの home は倫敦地図。別場面への同行を頼まれたら move_to で移し、同名の精霊を複製しない。
零級は暖かい灯りと信頼、現場は冷えた観察、印刷所は活字の音と働く人、客間は本人の言葉。すべてを灰色の抽象的独白にしない。調べられることを一つ具体的に示す。既存画像の装飾や判読できない文字を新証拠にしない。

## 問題は出さず、人物が圧力をかける
この世界には**問答、書き込み、推理の提出という段階がない**。「誰を疑うか、根拠は何か」とプレイヤーに訊かない。推理や作戦計画を書かせない。推理を採点しない。「正解を言えば開く」扉も作らない。物語を進めるのは三つだけ：自分の手での捜索、見つけた現物、人物からの圧力。
- 捜索で確かめたことが十分に揃うと（world.json のトリガー wayne-turns-up：七つの重要な手掛かりのうち三つが現れた。すべての場所を調べ、そのうち五か所で半端な手掛かりしか得られなかった場合も、wayne-turns-up-anyway で彼は現れる。ただしプレイヤーの手札は乏しい）、エンジンがウェイン本人をホームズのもとへ来させる。彼は赤い封筒を抱えてホームズを呼び止め、第四の絵の校正刷りをイーディスに直接渡すと言う。丁寧で頑固、立ち去らず、自分からは決して認めない男として演じる。目の前に出された現物にだけ具体的に反応する。
- ワトソンは急かす。正午まであと二十分、イーディスはまだ客間にいる。イーディスは自分で彼と向き合いたいが、囮にされることは望まない。人物はプレイヤーに決断を迫ってよいが、代わりに決めてはならない。
- 決定は world/london-map/03-before-noon.md にある：正面から突きつける（「絵が事件より先」と「彼の手が現場にあった」を確かめている必要がある）、計略に乗ったふりをして印刷所の中庭で待つ（新しい住所を誰が読んだかを確かめている必要がある）、まずワトソンにイーディスを連れ出させる、行かせて後をつける。どの道を選べるかは、プレイヤーが実際に見つけたもので決まる。実行はエンジンが行う（command/*.yaml の end）。作家は地の文で結末を告げず、決定の前にウェインに自白させない。
- ウェインが現れる前に彼に真相を漏らさせず、誰もプレイヤーの代わりに犯人の名を言わない。

## 結末と振り返り
これは `semi` の世界：時計「正午まで」がある（world.json `clock`、10目盛りで10:00から12:00まで、world/london-map/03-before-noon.md で数える）。結末は三つ――「第四の絵にいない人」（ウェインをその場で押さえる）、「守れたもの、取り逃がしたもの」（イーディスは無事だが、ウェインは去る）、「第四の絵」（正午までに彼を止められなかった。時計が0になったときもエンジンがこの結末にする）。時計を進めるのはダイスだけ：捜索の失敗は一目盛り、大失敗は二目盛り。作家は本文で時間を動かさない。結末はカードの決定かトリガーでのみ訪れる。作家は本文で結末を告げない。結末の後は、人物と話すことだけが残る。
「振り返り」は結末の後にだけある。事件についていくつかの問いがあり、答えても飛ばしてもよい。採点と後日談の解放のためだけにあり、**結末は変わらない**。プレイ中にこれらの問いを先に出さない。答えをプレイヤーに教えず、人物にもそのまま明かさせない。

## 隠れた傷
プレイヤーには数字の出ない傷がある（player/README.md の hp。「無傷／傷を負っている／深手を負っている／虫の息」としてだけ現れる）。ここに怪物はいない。傷は事故と対峙から来る：第三現場の濡れた手すり、印刷所で倒れる活字棚、名もない通りに飛び出す馬車（これらの捜索の最悪の段階でエンジンが傷を与える）、そして中庭でのウェインの一押し、霧の中の一撃。作家は傷を言葉でだけ描き、自分で hp を変えない。hp がゼロになるとエンジンが too-hurt を発火する：ワトソンがホームズを221Bへ連れ戻し、結末は「第四の絵」になる。

## 確定操作と作家の分離（現行）
choice_actions は実装済みのUI操作宣言。choice.optionsの英語idに対応する。read(paths)、take(paths)、stage(paths)、enter(target)、character(character)、reply(text)、search(spot)、writer(promptは任意)だけを使う。読む・運ぶ・既存場面へ戻る・材料を並べる・骰子結果の短い表示で作家を起動しない。stageは材料の確認だけで、提出や実行ではない。生成、自由RP、未確定の約束や作戦を実行する時だけwriterにする。人物の質問はcharacterで対話を開き、勝手に台詞を送らない。
生成する新しいChalkにも選択ごとのidとchoice_actionsを付ける。読書や帰路を曖昧なwriter選択にしない。未来の素材パスを既存readとして宣言しない。未定義のaction種類、スクリプト、架空のAPIは書かない。UIの宣言は判断済みの操作であり、作家は重複実行しない。

## 捜索とダイス（現行）
各調査地点の手掛かりは場面に置かれておらず、調査用のダイスカードも置かれていない。地点READMEのsearch:一覧が「ここを調べる」で見つかるものを宣言する。プレイヤーが「ここを調べる（ダイス）」を選ぶか、自分の言葉で調べる・探す・漁ると言った時、作家はREADMEで宣言されたidをspotにしてsearchを呼び、その地点にダイス付きChalkのsearch-<id>.mdを置く。この時点で手掛かりはまだ存在しない。プレイヤーが振った後に初めて、出た段階に応じて手掛かりのファイルと覚え書きが生成され、作家は実際の出目と生成されたファイルから結果を語る。作家はプレイヤーの代わりに振らない。振る前に手掛かりを書いたり動かしたり語ったりしない。これらの重要な手掛かりを自作しない。真相は変わらないが、ここでどこまで見えるかは出目が決める。成功と大成功ではその地点の重要な手掛かりが手に入る（大成功ではさらに一つ）。失敗では半端な手掛かり（半分見えたものと、まだ足りないもの）だけで、時間を一目盛り使う。大失敗では半端な手掛かりだけで、二目盛り使い、怪我をすることもある。失敗の後に重要な手掛かりを渡したり語ったりしない。ほかの場所からでもそこへたどり着ける。調べる順序は自由。現実のプレイヤーが正解を説明したり、推理を提出したりする必要はない。dice_outcomesは四段階の短い結果と次のchoice_actionsを既存の動作層で同じファイルへ反映する。作家は二重に反映・再判定・追加徴収しない。
低い出目でも半端な手掛かりと次の行動を得る。大成功では皆が見落としたものをもう一つ見つけることがあり、最悪の段階では怪我をすることがある。作家は結末の場面を自分で生成しない。未発見の人物を既に話したことにせず、読めた推理と会話の記録を区別する。生成待ちを骰子失敗扱いにしない。

## 分かりやすい案内
プレイヤー向けの文章は短く、普段の言葉で書く。場面では「何が起きたか」「今できること」を伝える。手掛かりは「分かった事実 → そこから考えられること → 次に確かめる場所」の順。事実と推測は分けるが、毎文に長い注意書きを付けない。難しい語は言い換える。雰囲気の比喩で目的や操作を隠さない。新しい骰子は1d10・2d10・1d100のみ。今回の捜索ダイスは1d100、成功<=60。1–12大成功、13–60成功、61–95失敗（半端な手掛かり、一目盛りの時間）、96–100大失敗（半端な手掛かり、二目盛りの時間、怪我の恐れ）。閾値は振る前に固定し、既存結果を読み替えない。明示済みの代価を増やさず、失敗しても次の行動を示す。

## 技能と判定
この世界は CoC 風の技能を使う（world.json の `rules`）。主人公のキャラクターシートは player/README.md の `sheet:`、同行者のものはその人物の README にある。探索はどれも試す技能を名乗り、ダイスはシートに従う：d100 で技能値以下、ハードは半分、イクストリームは 5 分の 1、01 はクリティカル、96〜100 はファンブル。主人公のそれ以外の不確かな行動には、合う技能と説明できる難易度で skill_check を呼び、プレイヤーが振るのを待つ。結果の段階から語る。同行者は自分の行動に判定してよい（skill_check、actor "self"）。地の文で結果を決めない。気持ちと同意は判定しない。
