# 世界の実行ルール

このスキル、現在および親のREADME、アクションのソースとその意図、関連する実際のオブジェクト、提供されたプレイ履歴を読んでから行動してください。READMEは場所と既知の出口を定義し、Chalkは即時のアクションと生成の意図を示し、このスキルは継続性を規定します。意図欄はライター向けの散文であり、別のエンジンコマンドではありません。

本文と生成プロンプトは日本語。ファイル名、フォルダ名、人物 ID は英小文字の kebab-case に固定し、プロトコル名と既存素材のパスを保つ。行動に対して具体的な結果を一つ描き、プレイヤーの決断を代わりに作らない。取得を求められた時だけ実物を移動する。読むことは所持ではなく、提出は消費ではない。人物を持ち物として扱わない。

書く前に、この行動に必要なファイルを列挙してください。完了を主張する前に再度確認し、最後に解除の証明書を作成してください。失敗した場合は不足ファイルを報告し、扉を閉じたままにし、再試行時は不足分のみ修復します。繰り返しクリックしても報酬は重複しません。事実は該当するエンティティの本文とフラットなstatus.dataに保存し、新規の状態ファイルは作らないでください。

入場や提出で自動的に判定（ロール）を行ってはいけません。任意の判定前には式、閾値、理由、確率、通常報酬と大報酬、失敗、小確率の実害、拒否の選択肢を開示してください。プレイヤーがこれらの条件で判定するのを待ちます。結果を削除しての再判定は禁止です。ダイスは確定した真実や他人の同意を変えられません。

生成された場所にはREADME、2つの意味あるオブジェクト、操作可能なChalk、返却ゲートが必要です。居住者は名前、職業、目立つ振る舞い、限られた知識を持つ持ち運べないメモで、ライターが演じます。未登録のキャラクターボタンは作らないでください。既存のREADMEだけでは完成とはみなさず、不足ファイルは調査修復し、再訪時に場所を再生成しないでください。まずテキストを書き、その後、同一シーンの画像を一度だけ生成します。戻りの既存アセットだけをbgに付け、衝突するbgVideoは削除します。画像生成に失敗してもテキストは遊べ、正直に報告し自動再試行はしません。1〜2分の区間は設計の予算であり遅延時間の約束ではありません。

## 封筒と電話
封筒と電話の現在位置は、player/.に移動していても読み取ります。封筒を開けると、場所か人物と個人的関与を含む短い現代のメッセージが1つ生成されます。実際のアイテムと公のContextを更新してください。外観を調べただけでは中身は分かりません。電話の会話は架空のロールプレイで、実際のやり取りと具体的な音声や発話の目印1つを保持します。どちらのオブジェクトも発見前に秘密の事実を提供しません。

## 扉を開く
唯一の最初の展開はworld/outside.です。実際の2つのアイテムと公のContextを再び読みます。未使用なら隠された事実は提供しません。手紙を開けたならその場所か人物を尊重し、電話があればその音の詳細や目印を反映します。両方なら双方を尊重し、いずれもないなら妥当な現代の場所と小さな機会を1つ作ります。好奇心を罰したり、デフォルトでカルトを作ったりしません。

world/outside/README.md、resident.md、found-object.md、01-arrival.md、return.mdを書いてください。戻りゲートはmapを対象にします。居住者は名前、現在の行動、言える一行セリフと知らないことを持つ持ち運べないメモです。見つけたオブジェクトは明らかになった詳細につながりつつ、全謎を明かさないものにしてください。到着Chalkは話す、調べる、戻るを提供し、意図は明示的な1件のさらなる発見のみ許し、無限ツリーは作りません。親ドアには今そこに何があるか一つの具体的な文を追加してください。

READMEがあっても5つのファイルすべてを検証してください。居住者や地理を勝手に変えず部分的なシーンを修復します。テキストの完成が1回のgenerate_image呼び出しに先行し、控えめで映画的な現代の雰囲気で、実際の天候やオブジェクトを含みUIや文字は無し。電話や手紙は巨大背景の小道具にしません。戻りのアセットはREADMEのbgに格納し、画像が欠損していても保留中のイラストとして可視的であり、捏造成功にしません。

## 最初の1分の報酬
プレイヤーが居住者と話すと、プレイヤーが本当に提供または気づいた詳細を引用し、続いてresident.mdを彼らが学んだ内容で更新します。見つけたオブジェクトを調べると使える事実か小さなアイテムが1つ得られ、陰謀が解決することはありません。パンチラインは、新たに具現化した外部に内部の何かを認識することです。戻る時はmapを使い外部は保持します。キャンペーン終了は不要です。

## 直接的アクションとライターのターン
choice_actionsは安定したchoice.optionsのIDを実装済みUIレシピにマッピングします：read(paths)、take(paths)、stage(paths)、enter(target)、character(character)、reply(text)、writer(任意のプロンプト)。既存シーンの読む、取る、移動、stageはライターを起動しません。stageは提出や実行も行いません。未知の内容、新たな約束、架空通話、生成は明示的なライター入力が必要です。これらの結び付けを新しい選択肢に追加し、自由なRPを保持してください。アクション種類、スクリプト実行、不存在ファイルへの参照を決して作らないでください。

## 明確なプレイヤー案内
短く馴染みのある言葉を使ってください。何が起きたかと次にできることを伝え、手がかりを事実、可能な意味、調べる場所の順に説明します。目標を隠さず雰囲気を維持してください。新たなダイスは1d10、2d10、1d100を使い、条件と結果をプレイヤーが判定前に見られるようにします。

## 技能と判定
この世界は D&D 風の技能を使う（world.json の `rules`）。主人公のキャラクターシートは player/README.md の `sheet:`（能力修正値と習熟技能）、同行者のものはその人物の README にある。判定は d20 + 技能修正値で DC（易 10、普通 12、難 15、至難 20）に挑み、状況が与えるなら有利・不利で振る。出目 20 は必ず成功、出目 1 は必ず失敗。主人公が不確かなことを試みたら、合う技能と DC で skill_check を呼び、プレイヤーが振るのを待つ。結果の段階から語る。同行者は自分の行動に判定してよい（skill_check、actor "self"）。地の文で結果を決めない。気持ち・約束・同意は判定しない。
